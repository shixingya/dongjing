# 动镜 DongJing · 初版产品需求文档 (PRD v1.0)

> 一句话定位：**打开摄像头，AI 实时识别你的动作，在家、办公室就能即时健身，矫正体态。**
> 形态：纯网页应用（无需下载 APP），全部 AI 推理在浏览器本地完成，画面不上传云端。
> 仓库：https://github.com/shixingya/dongjing

---

## 1. 背景与市场机会

### 1.1 赛道扫描

| 产品 | 形态 | 核心卖点 | 变现 | 借鉴点 |
|---|---|---|---|---|
| **BodyArcade** | 网页体感健身游戏 | 摄像头识别全身动作，躲障碍闯关，多人联机，本地推理 | 免费单人基础关；Pro $4.99/月（全关卡+报表+无限次） | 网页轻量化、游戏化留存、隐私本地化 |
| **Posiqo** | 网页 AI 动作教练 | 深蹲/俯卧撑等力量动作，**只统计标准有效次数，错误不计入**，实时语音纠错 | 免费每月 7 次；Pro $2.49/月 / $24.99/年 | 动作纠错的专业私教定位、低订阅价走量 |
| **BodyBuddy** | 网页姿态记录 | MediaPipe 记录姿态/组数/卡路里，实时反馈+训练计划 | Freemium：免费 20 动作；$4.99/月全课程；企业版 | 「C 端订阅 + B 端企业健康」双变现 |
| **FormMarker**（韩） | 网页动作分析工具 | 跳绳专项计数、动作对比回放、手势触发录制 | 年费订阅，偏教练/爱好者专业工具 | 动作复盘/回放是专业向差异点 |
| **慧动少年**（国内） | 网页+小程序 | 摄像头体态评估、跟练课程 | **B 端为核心**：学校/培训机构/企业员工健康采购；C 端+电商带货 | 体态评估入口 + 国内 B 端大单模式 |
| **ROR 在线体育**（国内） | 网页 AI 姿态识别 | 专业课程 | C 端年费 299；主力是企业员工健康 B 端采购 | 国内验证过的高收入路径 |

> Tempo / Form 等 AI 健身镜识别能力强但硬件绑定，非网页形态，仅作交互参考。

### 1.2 用户痛点

1. **去健身房时间成本高**：通勤+洗浴，单次实际投入 2h+，打工人碎片时间（居家 20 分钟、办公室 5 分钟）无人服务。
2. **没人盯着就练不对**：深蹲膝内扣、俯卧撑塌腰是最常见损伤来源，自拍回看成本高，私教贵。
3. **坚持不下来**：纯计数类 APP 无聊；游戏类产品（BodyArcade）好玩但纠错不专业，练完不知效果。
4. **隐私顾虑**：健身摄像头产品若上传画面，用户在家/办公室场景下强烈抗拒。

### 1.3 机会判断

- MediaPipe 姿态模型在浏览器端已能做到 30fps 级实时推理，**网页端"AI 私教"的技术门槛刚被抹平**；
- 海外 Posiqo/BodyArcade 已验证付费意愿（$2.49–4.99/月），国内尚无"轻网页 + 纠错专业度 + 体态评估"三合一的对标品；
- 国内变现天花板在 B 端（慧动/ROR 路线），但 B 端需要 C 端数据看板做交付物 → **先 C 端跑通训练-评估-报表闭环，是 B 端故事的地基**。

## 2. 产品定位与差异化

**定位：放在桌面上的 AI 体感私教（网页版）。**

差异化组合拳（取三家之长，避开三家之短）：

| 能力 | BodyArcade | Posiqo | 动镜 v1 |
|---|---|---|---|
| 网页开箱即用 | ✅ | ✅ | ✅（零安装，链接点开即用，无需下载 APP） |
| 只计标准有效次数 | ❌ | ✅ | ✅ |
| 实时语音纠错 | ❌ | ✅ | ✅ |
| 体态评估 | ❌ | ❌ | ✅（v1.7：两步 8 项，正面左右偏差 + 侧面矢状面头前倾/圆肩/骨盆前倾/膝过伸）|
| 训练报表/常见错误归因 | 基础 | 基础 | ✅ |
| 隐私（本地推理不上传） | ✅ | ✅ | ✅ |
| 游戏化关卡 | ✅ | ❌ | ✅（v1.4：星星收集 / 激光闪避 / 深蹲护盾）|
| 周课表 / 今日该练什么 | ❌ | ❌ | ✅（v1.6：按本机记录自动重算，弱项优先，额度排完自动换成关卡日）|
| 动作库覆盖坐姿/拉伸（办公可用）| ❌ | 部分 | ✅（v1.8：13 个动作，其中 5 个腿不入镜也能练，含侧平举与体侧伸展）|

核心体验承诺：**"错误动作不计入次数"** —— 每个动作都有可解释的标准（关节角度 / 摆动行程 / 指腕距离比 / 侧弯角度与停留时长），AI 像私教一样在你做错的一瞬喊出来。

## 3. 目标用户与场景

| 人群 | 场景 | 关键诉求 |
|---|---|---|
| 居家健身小白（25-40 岁） | 客厅 20 分钟自重训练 | 动作对不对没人说 → 语音纠错 |
| 久坐办公室人群 | 工位间隙 5 分钟 / 下班前 | 快速活动 + 体态问题（高低肩/头前倾） |
| 健身进阶者 | 居家力量日补充 | 有效次数统计、训练记录复盘 |
| （P2）企业 HR / 工会 | 员工健康福利 | 团队看板、批量授权（对标慧动/ROR） |

## 4. 版本范围（P0 / P1 / P2）

### v1.0（本 PRD 落地范围，P0）

- **F1 实时姿态识别**：MediaPipe Pose Landmarker（浏览器本地推理），33 关键点骨骼叠加，镜像预览。机位引导/校准阶段画面中央常驻一个半透明“示范小人”（按动作类型给站姿/坐姿/侧面俯撑模板，带呼吸浮动）提示站位；识别到真人后示范小人退场、真实骨骼以加粗发光脉冲“点亮”并持续跟随，形成从引导到接管的视觉连续性。
- **F2 十三个动作的"标准有效次数"引擎**（含坐姿上肢系与拉伸系，腿不入镜也能练）：
  | 动作 | 机位 | 有效次数规则（计数必要条件） | 实时纠错项 |
  |---|---|---|---|
  | 深蹲 | 正面 | 膝关节角 <115° 下蹲 → >150° 站直，全程无膝内扣 | 蹲得太浅(不计)、膝盖内扣、身体过度前倾 |
  | 俯卧撑 | 侧面 | 肘角 <95° 下放 → >160° 撑起，肩-髋-踝偏差 ≤16° | 塌腰/撅臀(不计)、下放不充分(不计) |
  | 开合跳 | 正面 | 双脚分开+双臂过头 与 并拢+垂手 完整交替 | 手臂未举过头、腿未分开 |
  | 弓步蹲 | 正面 | 双膝同屈 <120° 下沉 → 还原，左右交替 | 未下蹲到位(不计)、连续偏重单侧 |
  | 高抬腿 | 正面 | 膝盖抬高超过髋部为 1 次，要求左右交替 | 抬腿过低(不计) |
  | 平板支撑 | 侧面 | 保持躯干平直累计计时 | 塌腰、撅臀、低头 |
  | 摇头放松（坐姿） | 正面 | 鼻相对肩中线左右摆动行程≥约 0.3 肩宽的方向翻转 | 幅度不足提示 |
  | 挥臂激活（坐姿） | 正面 | 手举过肩后左右摆超 0.5 肩宽计一次 | 手未举过肩不计 |
  | 耸肩放松（坐姿） | 正面 | 肩中心相对头部上提超 0.12 肩宽 → 完全回落为 1 次（基准线慢速追踪自适应机位） | 耸肩幅度不足提示 |
  | 手掌抓握（坐姿，Pro） | 正面 | HandLandmarker 21 点：指尖-腕距/掌宽比值，张→握→张为 1 次，左右手独立计数 | 手未入镜/未完全张开提示 |
  | 侧平举（坐姿，Pro，v1.8） | 正面 | 每只手各自「垂体侧 → 腕升到肩线（0.25 肩宽内）→ 垂回 1.15 肩宽以下」为 1 次，上举全程最小肘角 <135° 则不计；尺度用肩宽而非躯干高（坐姿髋不入镜） | 未到肩高提示、弯臂上举(不计) |
  | 体侧伸展（v1.8，免费） | 正面 | 肩中点相对髋中点的侧弯角 ≥ 14° 进入周期，保持 ≥ 0.6s 后回正（<6°）为 1 次；只算幅度不算停留的话刷两下就会计次，对这个拉伸没意义 | 未侧弯提示、幅度不足(不计)、未停留(不计) |
  | 靠墙静蹲（v1.8，Pro） | 正面 | 计时类：左右膝角较小值落在 75–118° 且肩髋水平偏差 ≤ 0.22 躯干高才累计秒数，否则暂停计时（同平板支撑口径） | 蹲得不够低提示、胸往前塌提示 |
  > 坐姿系仅要求上半身关键点可见（鼻/肩/腕），校准与训练中不再强制髋膝踝入镜；抓握需额外懒加载手部模型（约 8MB，仅该动作触发下载）。一帧只能上报一个 rep，因此双臂/双手类动作（侧平举、抓握）同一帧完成的多个周期必须排队（`pend` 队列逐帧 shift），否则会静默丢计数。
- **F3 实时反馈通道**：画面 HUD（次数/组数/阶段提示）+ Web Speech 中文语音纠错（节流防重叠）+ 音效（有效"叮"/无效"嗒"，Web Audio 合成，无外部音频文件）。
- **F4 组训练流程**：课程 = N 组 × 目标次数（计时类为时长），组间休息倒计时，结束生成结果页（有效/无效次数、卡路里、动作问题归因、体面评分）；v1.3 起结果页额外产出**本次复盘**（数据→个人最佳对比→失分归因→下一步建议四句结构，可语音朗读，末句印上分享海报）。
- **F5 体态快速评估（两步·正面 + 侧面，共 8 项）**：先正面站立 6 秒采 6 拍 → 头颈侧移 / 高低肩 / 骨盆侧倾 / 躯干侧偏 4 项；再提示转身后侧身 6 秒 → 头前倾 / 圆肩 / 骨盆前倾代偿 / 膝过伸 4 项（矢状面，以关键点前后偏移 ÷ 身高归一）。输出体面评分 + 分级（良好/轻度/明显）+ 方向文案（如“耳在肩前方”）+ 拉伸建议，两次以上自动画趋势折线。不想配合转身可跳过侧面，退回只出正面 4 项的老口径。
- **F6 训练报表**：本周训练次数/总有效次数柱状、历史记录、TOP 常见错误、连续打卡天数；全部 localStorage，无后端。
- **F7 商业闭环占位**：免费 = 7 个基础动作（深蹲/开合跳/高抬腿 + 坐姿摇头/挥臂/耸肩 + 体侧伸展，拉低办公室门槛）+ 每月 6 次训练；Pro 解锁 6 个动作（力量类俯卧撑/弓步蹲/平板支撑 + 精细手指级手掌抓握 + v1.8 新增的侧平举与靠墙静蹲）；体感关卡、体态评估（含两步与趋势）、训练报表作为全量能力不设卡，先把留存与口碑做住。卡点只宣传真的锁了的东西（报表与趋势都全量开放，不得写进 Pro 卖点）。v1 定价页展示 ¥29/月、¥168/年，支付通道留占位（演示开关可激活 Pro 体验）。
- **F8 隐私承诺**：不上传任何画面数据（页面明示，代码审计无网络出口除模型 CDN 下载外）。隐私不只是合规注脚，而是首屏卖点（本地推理、全部数据只存本机）。

### P1（下一版本）

- ✅ **v1.1 已交付**：分享成绩卡片（canvas 海报，保存/复制 PNG）；动作对比回放（FormMarker 式，录制本地关键点序列而非视频，火柴人循环回放 1x/2x/0.5x）；每日目标环（训练点口径：1 有效次=1 点，计时每 10s=1 点，达成语音庆祝，与连续打卡共同构成留存闭环）；
- ✅ **v1.2 已交付**：循环跟练模式——自选 2–6 个动作（站/坐可混选）各做 1 组，动作间自动休息 10s 并引导重新摆姿势（逐动作校准），整轮只扣 1 次免费额度；每动作各写一条历史记录，结果页聚合总有效次数/时长/千卡/时长加权评分与问题归因，支持整轮再来一遍与循环海报；
- ✅ **v1.3 已交付（借鉴爆款开源项目经验）**：① **一句话编排**（学 ppt-master/diagram-design 的零门槛输入口）——用户说“办公室久坐肩颈酸来 5 分钟”，planFromText 纯函数按场景/部位关键词命中动作池、按时长定段数与重复轮数、自动跳过 Pro 动作并说明原因，输出可解释方案（含 why 理由与预计时长），一键开练或带回 chips 自己改；② **教练记忆**（学 claude-mem 的“不用复述背景”）——从本地历史提炼“某个动作出现最多且≥ 3 次的问题”，训练开始时语音一句“我记得你上次膝盖内扣出现了 9 次”，首页常驻“教练笔记”卡输出近 14 天最常失分项 + 建议；③ **训练复盘**（学 REA 的“干完活自己讲清楚怎么干的”）——结果页与循环结果页自动生成四句复盘，可语音讲解，并把建议句印进分享海报；④ **示范小人 + 骨架高亮**与隐私信任句强化（学 VoiceStudio 把“本地跑、不上云”当卖点而不是注脚）；
- ✅ **v1.4 已交付（体感关卡，对标 BodyArcade）**：同一套姿态引擎直接玩关卡，不额外下载模型——**星星收集**（左右跨步接住下落星星，高处的星星需举手过肩）、**激光闪避**（身体中心待在哪一半 = 在那一栏，跨步躲激光）、**深蹲护盾**（横梁压到胸口高度前蹲下开启护盾，不蹲扣血）。关卡逻辑为 exercises.js 里的 `makeGame(kind)` 纯函数（输入只有髋中心 x / 是否举手 / 是否下蹲，输出事件数组），渲染复用训练页 video+canvas（髋中心作为接球台，镜像与骨架对齐），难度每 15 秒升一档（生成间隔缩短、下落提速）；60 秒一局、3 格血（收集关不扣血只断连击）；口径拍板：关卡**不扣免费训练额度**（留存工具，拉时长不拉付费），关卡**得分不计入“有效次数”**但得分÷3 计入每日目标点，中途退出 discard 不存成绩；结果页复用：主数字为关卡得分、问题位换成“最高连击/结束方式/历史最佳”，复盘走游戏分支（记录新纪录、连击归因、下一局改什么），分享海报图标与文案同步适配；表现分口径：`min(100, 得分 / 标准线)`，标准线 collect 22 / dodge 16 / guard 12。
- ✅ **v1.5 已交付（移动端 / iOS Safari 专项）**：① **环境预检横幅**——微信内置浏览器无 getUserMedia（中文用户最常见的误入入口）、file:// 与 HTTP 被安全策略禁摄像头，均给一句可执行的处置指引（“点右上角···用 Safari/Chrome 打开”、“python -m http.server 8790”），而不是让用户对着黑屏猜；② **性能分级**——手机改用 640×480 采样 + ~18fps 检测（桌面仍 1280×720 / ~35fps），避免手机发热降帧到不可玩；③ **iOS 语音解锁**——首次用户手势里静音 speak 一次（否则 iOS 不肯让程序自己说话）+ 长句 pause/resume 心跳保活；④ **后台暂停与恢复**——visibilitychange 时 stopLoop（省电，且不把后台冻结的 rAF 误判成“没识到人”），回前台自动重接循环；pagehide 释放摄像头（相机指示灯不应长亮）；⑤ **竖屏适配**——手机竖屏时 stage 改 3:4 比例才能容下全身，矮屏弹窗内部可滚并采用 88dvh 防 iOS 工具栏遮挡，尊重 prefers-reduced-motion。
- ✅ **v1.6 已交付（本周课表：从“能练”到“知道今天该练什么”）**：① `makeWeekPlan(records, opts)` 纯函数——**一周从周一开始**，固定 7 个主题（下肢力量 / 肩颈放松 / 心肺燃脂 / 核心稳定 / 久坐激活 / 体感关卡 / 休息日），每天从主题池里挑最多 3 个动作；② **弱项优先**：用近 14 天各动作平均评分升序排序（没练过的给中性 75 分），于是你差的动作先排进课表，课表还能报出两个最弱项；③ **权限与额度是硬约束而不是提示**：Pro 动作只有订阅者能被排进去（免费版核心日自动降级为深蹲+耸肩），一个训练日 = 1 次循环跟练 = 1 次额度，**免费额度排完后的训练日自动变成不扣额度的关卡日**（带 note 说明原因）；④ **完成口径与每日目标环一致**（计时 10s=1 点、关卡得分÷3），历史里已有数据就能算出 done / met / missed / upcoming 四种状态与“还差 N 点：补做 X”文案；⑤ 首页课表卡：7 格可点击预览任意一天（含为何这么排的 why），按钮直接路由到 `startCircuit(ids)` / `openGame(kind)` / 休息日提示，不新建第二套训练入口；隔一天自动回到“今天”；⑥ 无随机数，因此可测可复现（单测覆盖 8 组场景：空历史/Pro/弱项/额度降级/达标未达标/折点口径/周日/关卡日）。

## 6. 指标（北极星与护栏）

- **北极星**：周人均有效训练次数（训练完成 × 次数质量）。
- 激活：打开 → 完成第一个有效次数 < 60s。
- 留存：次日 / 7 日；连续打卡 ≥3 天用户占比。
- 质量护栏：纠错误报率（有效被判无效）< 10%（阈值宁松勿严）；低端设备推理 ≥ 15fps。
- 商业化：免费额度触达率、Pro 页曝光→激活（v1 演示口径）。

## 7. 技术与非功能约束

- 纯前端静态站：单页 HTML + 原生 JS，无构建、无后端、无框架；CDN 引入 MediaPipe tasks-vision（首次打开需联网下载 ~5MB 模型，之后走缓存）。
- 摄像头安全上下文限制：浏览器在 file:// 下禁用 getUserMedia，需通过 http://localhost 或 HTTPS（GitHub Pages 默认）访问；页面本身双击可打开，训练功能需服务器环境（README 提供一行启动命令）。数据全部内联为 JS，历史存 localStorage。
- 降级策略：模型加载失败/无摄像头时，画面预览与界面不黑屏，给出明确引导（权限/HTTPS 要求）；语音不可用时降级为文字横幅。
- 兼容：Chrome/Edge 桌面为主；移动端 v1.5 已做专项（降分辨率/降帧保持续航、语音手势解锁、后台暂停恢复、竖屏比例、微信内引导换浏览器）；iOS Safari 真机手感仍需用户侧验证（无真机环境）。
- 摄像头需要 HTTPS 或 localhost 环境（file:// 下浏览器禁用摄像头）；帧率目标 24–30fps，推理用 video 帧时间戳去重。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 宽松衣物/半身出镜导致角度误判 | 校准阶段校验关键点 visibility，遮挡即提示"退后一步，全身入镜" |
| 侧面位只能看单侧（远侧肩、髋被躯干遮挡）| 关键链上只要一侧可见即取该项；踝不可见就不报该项，宁可少报也不编数据；评分取两视角均值 |
| 纠错误判挫伤体验 | 双级问题：轻微问题只提示不扣次数；关键问题才判无效；阈值保守 |
| TTS 中文音色在各系统差异 | 优先本地 zh-CN 音色，失败降级横幅；提供静音开关 |
| file:// 下 CDN 模型下载受网络环境影响 | 失败时保留预览+明确报错文案，支持换 https 部署 |
| 免费额度感知太强劝退 | v1 演示期提供"Pro 体验开关"；正式额度上线前 A/B |
